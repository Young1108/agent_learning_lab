协议选型与职责划分：MCP · ACP · CLI · A2A · Agent Card · Skill

根据通信两端角色与交互复杂度进行技术选型。MCP、ACP 与 A2A 分属不同层级，各司其职、互为补充。

架构选型建议
外层 Agent 通过 MCP knowledge_chat 调用知识能力时，应保留 MCP；先做好上下文边界治理。等未来演进出跨团队独立 Agent、长周期任务生命周期与复杂工件（Artifact）交付时，再在上层引入 A2A Adapter 进行异步任务委托，无须重写底层知识库。
场景MCPACPA2A选型要点
通信两端Agent ↔ 外部工具/数据源Client ↔ 本地 Agent独立 Agent ↔ 独立 Agent先明确两端通信实体，再定协议架构

Agent ↔ 工具

MCP

统一工具、API 与数据源的接入规范，强调参数校验与结构化返回结果。

类比：为智能体装上标准化的通用接口
Client ↔ Agent

ACP

宿主软件拉起本地 Agent 子进程，通过 stdio/RPC 高效驱动代码编辑与交互。

类比：IDE 与本地助手之间的专属双向会话通道
本地进程

Agent CLI

原生支持 stdio 通信的本地编码智能体，直接操作工作区代码库。

类比：常驻终端的自动化结对开发助手
Agent ↔ Agent

A2A

面向独立部署智能体之间的服务发现、任务委派与长流程状态流转。

类比：多智能体分布式协同与工作流协议
公开身份

Agent Card

对外公布的机器可读名片，包含端点地址、认证方式与能力范围描述。

类比：分布式服务契约，不同于内部的 SKILL.md
分层架构设计实践
编辑器 / IM 宿主
  └─ ACP：拉起本地 CLI Agent，通过 stdio 驱动完整编码交互

核心业务 Agent
  ├─ MCP：短请求、确定性工具调用、knowledge_chat
  ├─ ACP：在需要本地编码辅助时，与本地工作区 Agent 对接
  └─ A2A：长周期任务、异步协作、跨团队独立 Agent 委托

知识库 / 内部服务
  └─ MCP：内部检索、HSCode、合规等业务工具接口

避坑提示：避免将完整长会话 Agent 粗暴包装为单次调用的 MCP 工具；A2A contextId 可映射为底层的会话 ID

常见概念辨析
Tool Calling 解决模型如何调用函数；MCP 规范了工具与数据源的接入标准；ACP 解决了客户端（如 IDE）如何精确控制本地 Agent 进程；CLI 是可直接在终端交互的实体程序；Skill 是工程层面的工作流编排规范；Agent Card 与 A2A 则是跨网络 Agent 互相发现与委托协作的标准。按实际场景选择协议层级，切勿过度设计。

3

Skill：构建模块化、低上下文损耗的能力包

Skill 并非单纯把 Prompt 写长，而是按需渐进加载的工程规范：先路由匹配，再加载核心流程，细则与脚本仅在执行时按需读取。

核心结构
一个标准 Skill 真正必需的只有：一个独立目录 + `SKILL.md`。`references/`、`scripts/`、`assets/` 都是按需添加的可选资源，不是必需项。

最小形态 vs 推荐结构

最小 Skill
my-skill/
└── SKILL.md
完整推荐结构
my-skill/
├── SKILL.md
├── agents/openai.yaml
├── scripts/
├── references/
└── assets/
构件分工原则
`SKILL.md` 是操作流程规范，`references` 是参考资料库，`scripts` 承载确定性自动化脚本，`assets` 存放产物样板与模板，协同构成完整的工程化能力包。

三级加载：降低上下文开销

第一级 · name + description
常驻上下文的轻量描述：负责意图匹配与触发判断。
第二级 · SKILL.md 正文
命中后载入：包含执行步骤、分支决策、验收规范及资源索引。
第三级 · references / scripts / assets
特定任务分支需要时按需读取，避免一次性塞入全部资料导致上下文膨胀。

优秀 Skill 的工程标准
目标不是强制要求每次输出字字一致，而是确保 Agent 每次都遵循清晰可预测的工程流程。入口流程在 `SKILL.md`，业务文档与规范按需读取，确定性逻辑交由自动化脚本稳定执行。

场景诊断：工程实践与信号定位

面对复杂的 Agent 异常现象，从可观察的系统信号切入，快速定位问题究竟出在执行环境、闭环控制还是全局治理层。

01

执行中断与环境盲区

Agent 编写代码逻辑正常，但每次执行遇到报错时，都必须依赖人工手动复制控制台日志或截图喂给它才能继续。

02

多轮反复与无限重试

在本地手动调用单次执行非常顺利，但一旦配置为无人值守的定时自动化任务，就会陷入反复修改同一处代码、甚至无限重试直至超时。

03

局部指标达标但全局结果恶化

代码生成速度提升、单测覆盖率达标、局部打分全绿，但交付到用户环境的实际业务留存率和满意度持续下滑。
